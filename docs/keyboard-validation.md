# Jarvis 中文键盘手动验收

2026-09-24：顶部改为三条横排回复候选，下方保留离线全拼、英文、数字、符号输入。
本次仅完成静态检查，没有执行编译、安装、模拟器或真机测试。

在 Xcode 安装主 App 和键盘扩展后，在系统“设置 → 通用 → 键盘 → 键盘”添加 Jarvis。
工程使用同步文件夹，`PinyinInputEngine.swift`、`pinyin.tsv`、许可/来源说明属于键盘 target；
在 Xcode 检查 `pinyin.tsv` 已进入键盘扩展的 Copy Bundle Resources，缺失会没有中文候选。

## 普通输入（不开始录屏也应可用）

- 在微信输入框通过地球键选择 Jarvis。确认“暂无回复建议”下仍有完整按键。
- 输入 `nihao`，选择“你好”；输入 `nihaoshijie`，既可一次选词，也可选“你好”后继续选“世界”。
- `xi'an` 能选“西安”；先选“西”时剩余拼音为 `an`，不能留下开头的分隔符。
- 检查 `nv`、`nve`、`lve`、`zhanlve`、`nver` 的候选包含“女、虐、略、战略、女儿”。
- 输入 `yi`，横滑并点“更多”能继续查看低频同音字；不会只剩三种字可选。
- 空格有组合时仅选词，无组合时输入空格；回车有组合时先上屏原文，不同时换行。
- 中文标点前可提交完整中文候选；中英/数字切换、地球键、收起键盘前保留未选拼音原文。
- 检查英文大小写、数字、符号、删除和长按删除。已有草稿不应被整段清空。
- 在横竖屏、小屏幕及深色模式检查按键、来源确认、底部安全区和候选横滑。
- 切换输入文档后，旧文档的未提交拼音不能进入新文档。

## 分析回复与画中画

- 只停留在一屏清晰聊天（可少于设置的上下文条数），应开始分析；最后一句是自己发出的也应展示情绪判断。
- PiP 四行分别检查来源/情绪程度、意图/缓解状态、需求/行动、候选/进度。上下文提示变蓝时左侧危险色条仍保留绿/橙/红。
- 分析中向上补历史，不应清空 PiP；新消息/换联系人时显示上次结果和来源，新 Jev 判断完成即替换，无需等候选完成。
- 只有裁切气泡的一屏仍应在“当前屏 OCR”中显示文字并分析，模型输入带“部分可见”说明；不得一直显示“等待画面稳定”。
- Judge 快、Reply 慢：PiP 先显示新判断，同时提示候选生成/排序中；Reply 失败不能阻止情绪显示。
- Reply+Rank 快、Judge 慢或失败：键盘可先显示三条候选；同请求 Judge 后完成时补充摘要，不混入上次请求摘要。
- 导出长图或后台编码较慢时，OCR、Jev 与候选仍可更新；图片槽覆盖不应丢失段合并元数据。暂停/停录时在途图片合并可存完，但不能重新触发模型或候选。
- 连续产生超过 6 个无重叠片段，不应崩溃；无方向证据的新屏应独立分析，不能继续显示旧屏候选为当前结果。
- 纯图片停住超过 3 秒不应反复新建空段；离开聊天到无标题空页面应停用候选。
- 把 PiP 拖到下方，再在聊天里发一条“Jarvis 今天可以用吗”，确认真实聊天不被前缀过滤、PiP文案不混入消息。
- 缓存超过 50 条且模型要求查历史，第二次输入窗口相同不应重复补算；有缺口时模型输入应保留明确缺口提示。
- 模型响应较慢时暂停/停止录屏或关闭自动分析，旧 OCR/旧网络回调不能恢复候选或覆盖结果。
- 配好判断和回复接口，开始录屏，停留在有文字消息的聊天页；分析完应显示三条候选已就绪或具体失败原因。
- 露出联系人标题分析一次，再用 PiP 遮住标题；如果从未识别标题，键盘应显示“当前会话”和人工核对来源提示。
- 没确认来源前，回复不可插入；确认后点击回复在光标处插入，仍可继续用下方键盘修改。
- 确认后候选栏的说明行显示判断摘要；旧结果等待更新期间，主 App 的旧候选也不可复制。
- 选中草稿再点回复，应先提示替换，三秒内再次点击才替换选中内容；不自动发送。
- 有拼音组合时点回复，应先提示完成选词，不能悄悄丢弃正在输入的内容。
- 从停止录屏到重新录屏，状态原因应更新，不残留“录屏已停止”。
- 停录、离开聊天、换会话、新消息及建议过期后，回复禁用，普通输入仍可用。
- 没有新帧超过 15 秒时建议失效；同一条分析最长 120 秒，不能靠界面计时器无限延长。
- 缺少回复接口、排序失败或共享文件写入失败时，PiP 应显示实际原因而非笼统“分析完成”。

## 当前边界

- 截图仍需识别为聊天版式；没有可读消息会明确显示原因。OCR 不识别图片内实际语义。
- 当前每个接受的帧都执行 OCR，由单槽队列限制积压；需真机检查识别耗时、功耗和温度。
- 使用自有离线全拼词库，不具备系统输入法的模糊音、简拼、个人学习或语音输入。
- 不能向苹果/搜狗候选栏注入回复；Jarvis 自身的输入区和候选区共同显示。
- 来源确认仍需用户核对；OCR 和输入文档 ID 不能可靠识别所有跨联系人切换。
- 未选词的拼音只在扩展内存里，系统终止扩展会丢失该部分；已插入目标输入框的草稿不受影响。
